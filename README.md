# ADMT CA2 — Social Media Analytics

## Objective
Demonstrate reproducible Extract-Transform-Load and six SQL OLAP operations over a SQLite star-schema data warehouse.

## Data provenance
All data is SYNTHETIC and generated deterministically using seed 51. Sources: `sources/posts.csv` (1,204 raw rows), `sources/creators.csv` (60 creators), and `sources/campaigns.json` (3 campaigns). Manifest hashes are in `sources/manifest.json`.

## ETL
Extract source CSV/JSON; validate required IDs, dates, platforms, and metrics; reject invalid records; detect exact duplicates and fail on conflicting IDs; enrich date, creator and campaign attributes; compute engagements; map unknown creator/campaign/content to dimension key 0; load SQLite.

## Warehouse
`warehouse/social_media_ca2_dw.sqlite` has one `fact_post` (grain: one row per accepted post) and five dimensions: date, platform, creator, content, campaign. Foreign keys and nonnegative metric checks are enforced.

## OLAP
Q1 Roll-up: month. Q2 Drill-down: region to country. Q3 Slice: Instagram. Q4 Dice: platform/content/quarter/campaign filters. Q5 Pivot: platform x quarter. Q6 Aggregation: campaign objective. Supplementary queries cover content, creator activity tiers and month. Weighted engagement rate is 100 * SUM(engagements) / SUM(impressions), excluding zero denominators.

## Run
Open `Social_Media_Analytics_CA2_FINAL.ipynb` in Google Colab and select Runtime > Restart session and run all. The notebook generates files under `/content/social_media_ca2/`. No manual dataset upload or API key is needed. Run the final download cell to retrieve the ZIP.

## Artifacts
`results/` contains query CSVs, SQL scripts, quality logs, report comparison, and report corrections. `charts/` contains three analytics charts and a star-schema diagram. `evidence/` contains the full validation checklist.

## Limitations
These are synthetic records, not observations of real users. Creator activity segments represent posting frequency, not demographic audiences. Historical report figures were generated by a different dataset and do not necessarily match the final notebook. Consult `results/report_corrections.md` before presenting those numbers.
